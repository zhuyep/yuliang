# 本机今日解读：使用、数据和模型边界

## 启动

```sh
npm run dev
```

访问 [余量](http://127.0.0.1:4173)。默认可使用合成示例和日汇总文件，未配置数据连接时不会自动冒充真实数据。旧规则界面保留在 `/index.html`。

维护者现有本机 Docker 数据库已安装时：

```sh
YULIANG_DATA_SOURCE=garmin-grafana-influxdb npm run dev
```

连接只使用固定的 SELECT 查询，通过现有 InfluxDB 容器的只读账号读取数据。密码留在容器内部，不进入网页、模型、进程参数或源码。此适配器默认读取名为 `garmin-local-influxdb-1` 的已有容器；可用 `YULIANG_GARMIN_DB_CONTAINER` 指定其他合规容器名。它不安装或修改第三方采集器，不登录 Garmin，不触发 Garmin 同步。旧值 `garmin-docker` 仅为已有本机配置保留。

“读取本机数据”只重新读取数据库；“设备最后上传”和“本页读取”分别显示，不混为一次成功同步。没有安装定时同步或自动调度。

## 当前能力

- 五项标准化日指标：睡眠时长、夜间平均 HRV、静息心率、晨起 Body Battery、步数。压力与运动训练负荷尚未进入本轮分析。
- 显示数据日期、缺失项、此前 28 天窗口中的有效天数及中位数。当前日排除在历史基线之外；少于 7 个有效历史日不计算个人常态。该门槛是产品规则，不代表临床有效性。
- 当天未结束的步数不与历史全天步数作差。缺失、无效、零值分别处理。
- 过期、同步时间未知、历史不足或关键指标缺失时，不生成当天的训练调整；不适覆盖设备数据。当前建议不构成诊断，规则未经临床验证。
- 本机依据查询明确标为“非生成式 AI”，支持指标与安排依据，不能自由回答所有问题。
- 用户反馈与当时的依据一并保存，可刷新后回看、补记结果；相同版本的重复保存更新同一条记录。每个存储最多 365 条，满时拒绝新建，不静默删除旧记录。

反馈保存在用户目录下 `.local/share/yuliang/feedback.json`，不在仓库或同步工作区内；目录 700，文件 600。包含敏感健康摘要与主观反馈，不应上传、共享或发给模型。合成演示的反馈不落盘。反馈只有在用户点击保存后写入，没有收集使用遥测。

## 日汇总导入

新界面使用以下格式（与旧原型 JSON 格式不同）。文件上限 100 KB，最多 90 天，日期按上海时区。缺失指标用 `null` 或省略，不填零；日期不可重复。程序会忽略无关字段，不保存原始文件。

```json
{
  "demo": true,
  "syncedAt": "2026-09-05T08:00:00+08:00",
  "days": [
    { "date": "2026-09-04", "sleepMinutes": 430, "hrvMs": 45, "restingHeartRate": 56, "bodyBatteryMorning": 66, "steps": 6100 },
    { "date": "2026-09-05", "sleepMinutes": 400, "hrvMs": 42, "restingHeartRate": 58, "bodyBatteryMorning": 59, "steps": 1200 }
  ]
}
```

上例完全合成，只有两天，预期显示历史不足。本人真实记录不要标记 `demo: true`。导入内容发送至本机服务内存进行计算，不发送至互联网；只有明确保存反馈时才保存对应的必要依据。

## 可选本地生成式 AI（默认关闭）

已实现 Ollama 的本地 `/api/chat` 适配接口。没有下载模型、启用云模型、探测其他项目的 API 密钥或自动把真实记录发给模型。

用户明确选择本地模型，并自行准备实际安装的本地模型后，设置 `YULIANG_OLLAMA_MODEL` 为该模型名称再启动。默认仅允许合成示例进入模型；真实健康摘要还需要用户明确同意后设置 `YULIANG_ALLOW_LOCAL_HEALTH_AI=yes`。云端模型服务与数据发送范围仍待用户选择，当前没有云端适配器。

启用前必须在 **Ollama 服务进程** 设置 `OLLAMA_NO_CLOUD=1` 并重启该服务，核对服务日志的 cloud disabled 状态；仅给余量进程设置该变量无效。不要把云端代理模型当作本地模型。[Ollama 官方本地模式说明](https://docs.ollama.com/faq#how-do-i-disable-ollama-cloud-features)

每次请求先通过 `/api/show` 核验模型元数据，探测请求只有模型名，没有健康摘要或用户问题。拒绝 cloud 名称、远程模型字段和缺少本地 GGUF 架构信息的结果；无法核验时不发送后续健康提示词。目前不支持其他本地模型格式。元数据检查依赖可信且未被并发改写模型的本机 Ollama 服务，并非网络隔离的替代品；实际启用时仍须核验关闭云功能。

模型只获得必要证据与当前问题，不获得 Garmin 登录令牌、数据库密码、GPS 或任意工具权限。回答必须引用存在的证据 ID，新增数字、行动建议类措辞及部分危险表达会被拒绝；生成式部分只解释指标事实，不给活动处方。缺失、陈旧和不适场景直接使用确定性说明，不让模型改写行动边界。模型超时或回答被拒绝时显式回退。

这些输出检查不是医学验证，也不能保证检测到所有编造、因果错误或变相行动建议。关键词过滤存在漏检和误拒绝，不能视为安全保证；实际启用前需针对选定模型额外评估解释质量与安全边界。模型生成结果仍需人工判断；不能根据一次体感反馈自动重训或修改安全规则。

协议参考：[Ollama chat API](https://docs.ollama.com/api/chat)。当前测试通过合成数据与替代传输验证协议和回退；实际模型运行效果须在选定模型后另外验收。

## 验证与发布

`npm run check` 包含计算、日期、缺失/陈旧、不适覆盖、数据库映射、API 访问控制、反馈持久化与模型回退测试。测试只使用合成数据和临时目录，不访问 Garmin。

服务仅监听本机。API 检查 Host、Origin、跨站来源与页面会话令牌；私人文件和源代码仍不通过静态文件路由提供。该设计不是多用户鉴权方案，不能直接部署到公网。

本仓库以公共预览方式开源。公开可见不代表允许云模型、额外账号接入、扩大同步范围或上传个人数据；这些边界不由普通代码变更自动放宽。
